# 中計画: FFmpegロード高速化・プリロード (03_ffmpeg_preload.md)

## 現状の課題
- FFmpegのロードはユーザーが「ダウンロード」を押したときに初めて `ensureOffscreenDocument()` -> `initFFmpeg()` -> `ffmpeg.load()` を行う。
- `ffmpeg-core.wasm` (32MB) のフェッチおよび WebAssembly コンパイルに数秒〜数十秒かかり、ユーザーが「えぐい時間かかってる」と感じる最大のボトルネックになっている。
- ポップアップを開いた時点、あるいはストリーム検出時点でオフスクリーンドキュメントを事前初期化（warm up / preload）しておけば、ダウンロードボタン押下時にはすでにFFmpegロードが完了しているため待ち時間がほぼゼロになる。

## 解決方針
1. `offscreen.ts` にて、オフスクリーンドキュメント起動時にバックグラウンドで `initFFmpeg()` を先行開始する（ダウンロード要求が来る前にコンパイルを完了させておく）。
2. `background.ts` でストリームが最初にキャプチャされた時、または拡張機能起動後、オフスクリーンドキュメントをアイドル時に先行作成（プリロード）。
3. キャッシュ戦略: WebAssemblyのコンパイル結果やファイルをIndexedDBやブラウザキャッシュで効率よく扱えるようにし、2回目以降の初期化をミリ秒単位で完了させる。
4. 進捗表示: もしロード中であっても、ユーザーに「FFmpegエンジンを準備中 (ロード済み/未ロード)」のステータスを可視化する。
